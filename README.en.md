# Aria del Pavese

Interactive map of all the ARPA Lombardia air-quality monitoring stations across the province of Pavia (Italy), from Lomellina to Oltrepò: daily values for the last ten years,
exceedances of legal limits highlighted, per-station trends by week, month or year. A static site on GitHub Pages, refreshed
every night. The user interface is in Italian.

<br clear="left">

**Live site:** <https://danbas.github.io/aria-del-pavese/>

> **Independent project.** This is not an official site and is not affiliated with ARPA Lombardia, Regione Lombardia or any
> local authority. The computations are the project's own; for official purposes refer to ARPA data.

## Why

The project starts from a simple question: *how was the air in the province of Pavia on a given day, and where?* ARPA publishes
everything as open data, but raw hourly values are not readable at a glance. The page shows, for any date in the last ten years,
what the province's stations measured, flags the days above the limits, and lets you follow a station over time.

## What it shows

- the 13 ARPA stations of the province (including decommissioned ones, with their active periods) and the pollutants each one measures;
- for the selected date, the values of every visible station, with exceedances of legal limits in red and of the WHO guideline in amber;
- for one station at a time, a chart of the chosen pollutant over the week, month or year, with the threshold drawn;
- a PDF report for the chosen station and period (one or more pollutants, chart, values table, exceedance count), generated entirely in the browser;
- a vector map of the province (ISTAT municipal boundaries); an OpenStreetMap background can be switched on.

## Repository layout

| Path | Contents |
|---|---|
| `scripts/fetch_arpa.py` | downloads from dati.lombardia.it (Socrata API) and aggregates by day → `data/arpa-pv-YYYY.json` |
| `scripts/build_data.py` | builds `site/data.js`, the compact bundle read by the page (generated by the workflow, not versioned) |
| `data/` | daily aggregates of **closed** years (up to two years ago) and simplified ISTAT municipal boundaries |
| `data/open/` | current year, previous year and sensor registry: re-downloaded every night, not versioned |
| `site/` | the page (`index.html`, `style.css`, `app.js`), logo, fonts and vendored libraries (Leaflet 1.9.4, Chart.js 4.4, jsPDF 4.2.1 + AutoTable 5.0.8) |
| `.github/workflows/update.yml` | nightly cron: fetch → build → commit data → deploy to Pages |

## Setup

1. Create a public GitHub repository and push this folder to the `main` branch.
2. In **Settings → Pages** set *Source: GitHub Actions*.
3. In **Settings → Actions → General → Workflow permissions** choose *Read and write permissions* (needed for the automatic data commit).
4. Optional: add a `SOCRATA_APP_TOKEN` secret (free token from the developer settings on dati.lombardia.it) to avoid API throttling.
   It works without one.
5. Run the workflow from **Actions → Aggiorna dati ARPA e pubblica → Run workflow**. The site will be at `https://<user>.github.io/<repo-name>/`.

Every run — including the one triggered by the push — downloads the current and previous year (5 API calls, under a minute) and rebuilds the site.

During the first tests it is worth adding `<meta name="robots" content="noindex">` to `site/index.html`, to be removed at go-live,
so the page is not indexed before it has been verified online.

## Local use

```bash
python scripts/fetch_arpa.py --years current,previous   # or --years all, or --years 2024,2025
python scripts/build_data.py
python -m http.server -d site 8000                       # http://localhost:8000
```

No dependencies beyond the Python 3.10+ standard library. Do not commit `data/open/`: it is already in `.gitignore`. To adapt it to another province of Lombardy, change `PROVINCIA` in
`fetch_arpa.py` and replace the two boundary GeoJSON files.

## How the values are computed

One value per sensor per calendar day (date of the ARPA timestamp), using only records with status "validated" (`VA`):

- **daily mean** for PM10, PM2.5, SO₂, benzene, NH₃, NOₓ, black carbon;
- **hourly maximum** for NO₂ (and SO₂, for the 350 µg/m³ hourly limit);
- **daily maximum of the 8-hour running mean** for O₃ and CO (a window is valid with at least 6 of 8 hours).

Days with fewer than 18 valid hours are marked as partial. The "validated" (`VA`) status is an automatic per-reading quality check, not a certificate that the data is final: current-year data (and, until March 30, the previous year's) remain provisional and ARPA can still revise them retroactively. Thresholds are those of Italian Legislative Decree 155/2010
(Directive 2008/50/EC). PM2.5 only has an annual limit (25 µg/m³): as a daily threshold the WHO 2021 guideline (15 µg/m³) is used,
labelled as a WHO reference rather than a legal limit. Directive (EU) 2024/2881 will introduce stricter limits from 2030.

Datasets used: `ib47-atvt` (stations), `nr8w-tj77` (2010-2017), `g2hp-ar79` (from 2018, closed years), `nicp-bhqi` (current year).

**Sliding window and size.** The page shows the last ten calendar years (`WINDOW_YEARS` in `build_data.py`), so the `data.js`
bundle stays at a constant size (~1.5 MB) as years go by. Only *closed* years (up to two years ago), which never change again,
are versioned in the repository: git history grows by about half a megabyte per year, in a single commit in January when a
year matures. The current and previous year are re-downloaded every night into `data/open/` (git-ignored), because ARPA
validates retrospectively and values from earlier weeks may change. When ARPA moves a just-closed year from `nicp-bhqi` to
`g2hp-ar79` there may be a window in which the download comes back empty: in that case the script keeps the existing file.

## Disclaimer

The aggregations, exceedance counts and 8-hour running means are the project's own processing of ARPA validated data and may differ from
official statistics. The information is provided as is, with no warranty of completeness or accuracy, and does not replace
official communications from ARPA Lombardia or health authorities.

**Privacy.** The page uses no cookies or tracking and collects no personal data; preferences stay in the visitor's `localStorage`.
Fonts and libraries are served with the page, and the PDF report is generated entirely in the browser too, so no request goes
to third parties — except OpenStreetMap tiles, requested from OSM servers only if the visitor switches the background on.
